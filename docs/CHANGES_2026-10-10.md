## What changed, per task

### Task 2: secrets isolation
- New `agent/sandbox.py`, the only file under `agent/` that starts processes.
- Commands that run repo code (venv, pip, uv, pytest, the import probe) get an environment built from an
  allowlist, then a denylist. `GEMINI_API_KEY` and the GitHub token are not in it.
- After the review: `git` gets the same clean environment, with hooks, `core.fsmonitor` and the `ext::`
  transport switched off. Only clone, fetch and push receive the token.
- A clone that stored the token in `.git/config` is refused.

### Task 1: syntax-error fast path
- `repo.syntax_errors` finds files that do not parse without running code.
- `runner.collection_errors` exposes the file and message of each pytest collection error.
- New `syntax` step between `map` and `localize`: no localize call, a dedicated prompt, edits limited to
  the broken files, proof in code (files parse, test modules import, no regression), shared retry budget.
- A debug run ends after the repair only when no test fails and the model says nothing else was asked.
- The report has a "Syntax stage" section.

### Task 3: persistent projects
- Each repository is a project in `projects/<project_id>/`: `workspace/` on branch `codefix/<name>`,
  its own `venv/`, and `runs/<run_id>/`. History is in `data/codefix.sqlite`.
- A run continues from the project head. Success leaves exactly one commit; anything else puts the head
  and files back. A run interrupted by a server stop is rolled back by the next run.
- One venv per project, rebuilt when the dependency files change, evicted least-recently-used.
- Reset (with archive tag), Sync (rebase, abort on conflict), Export (patch by default), one pull
  request per project, delete.
- New API under `/api/projects`, 409 when a project is busy, 404 for another user's project.
- CLI: `--reset-to`, `--sync`; prints env reused/rebuilt and the project head.
- UI: Projects card, project view with run history, Reset and Delete dialogs, live run with step
  timings and "What this run builds on". `frontend/dist/` is rebuilt.

### Removed on purpose
The `agent-changes` branch, the automatic export to `AGENT_OUTPUT_DIR`, creating a branch inside the
user's own local repo, the run-time "fork or local?" question (`awaiting_approval`, `/approve`), and
the CLI flags `--fork` / `--local`. A run never pushes; the pull request is a project action.

## Remaining risks
- **No container.** Repo code runs as the same OS user, can read that user's files (including git and
  gh credentials on disk) and has network access.
- **Planted git config.** See F1: closed for local commands, not fully for fetch and push.
- **Fail-first can be sidestepped inside a broken file.** A logic fix made in the same file during the
  syntax repair, with no test covering it, ends as "syntax only".
- **Flaky tests** still look like regressions (tests run once).
- **Upstream drift.** A long-lived project branch can conflict on Sync; conflicts are never resolved
  automatically.
- **Lock is per process.** The CLI and the server on the same project at once are not protected.
- **Export with confirm** overwrites whatever is in the original folder now.
- **Proxy and private index settings** are not passed to pip.
